# v0.3.1 稳定化说明

v0.3.1 是 v0.3.0 事件通知系统的稳定化补丁，目标是把已经交付的 Hook sink 化、notification rule、dispatcher 并发背压和 17 个语义事件整理成可发布、可迁移、可运维的版本说明。

本版本不引入新的数据库 schema，不新增事件类型，也不扩大 adapter 生态范围。

## 范围

- 固定 Hook 与 notification rule 的事件白名单：`task.created`、`task.modified`、`task.completed`、`task.deleted`、`task.started`、`task.stopped`、`task.assigned`、`task.unassigned`、`task.blocked`、`task.due_changed`、`task.priority_changed`、`task.project_changed`、`task.tags_changed`、`task.unblocked`、`project.archived`、`project.annotated`、`project.denotated`。
- 明确任务生命周期事件语义：`start` 只触发 `task.started`，`stop` 只触发 `task.stopped`；普通修改触发 `task.modified`，涉及 assignee、due、priority、project、tags、blocked 状态时额外触发细粒度事件。
- 明确阻塞事件边界：任务从非 blocked 变为 blocked 时触发 `task.blocked`；从 blocked 变为非 blocked 时触发 `task.unblocked`；完成任务保持 unblocked 语义。
- 统一 payload 约定：`task.*` 事件携带标准 task 快照，差异字段放在 `task` 之外；用户身份字段继续使用完整 `task.UserInfo` 结构，不退化为裸 UUID。
- 强化出站投递说明：delivery 生成时冻结 URL、method、headers、body 和 content type；retry/replay 使用历史快照，不按当前 sink 模板重新渲染。

## 迁移提示

从 v0.3.0 开始，Hook 不再直接保存 URL 或 secret。旧的直接 URL hook 模型应迁移为：

1. 使用 `xuanchu notification sink add ...` 创建 workspace 级 sink。
2. 使用 `xuanchu hook add ... --sink <sink-ref>` 或 `xuanchu notification rule add ... --sink <sink-ref>` 引用 sink。

如果旧集成只监听 `task.modified` 来捕获所有任务变化，需要按真实意图补充订阅：

- 需要开始任务事件：订阅 `task.started`。
- 需要停止任务事件：订阅 `task.stopped`。
- 需要字段级变化：订阅 `task.assigned`、`task.unassigned`、`task.due_changed`、`task.priority_changed`、`task.project_changed`、`task.tags_changed`、`task.blocked`、`task.unblocked`。
- 需要普通编辑：继续订阅 `task.modified`。

建议下游系统把 `delivery_id` 作为幂等键。`attempt` 字段可能来自入队时的冻结上下文，本次 HTTP 请求的真实尝试次数以 `X-Xuanchu-Attempt` header 为准。
