# v0.3.2 日志可观测性与 MCP 反代修复

v0.3.2 是 v0.3.x 的运维补丁，聚焦两个线上问题：日志文件没有记录常规运行信息，以及 HTTP MCP 经反向代理访问时被 Host 保护拒绝。

## 变更

- `xuanchu server` 的日志文件现在会记录 server lifecycle、HTTP access、MCP tool/resource 调用、notification/hook dispatcher 投递和 reminder scheduler 扫描。
- operation log 使用结构化字段，包含 `component`、`operation`、`request_id`、`actor_user_id`、`token_id`、`delivery_id`、`rule_id`、`result`、`duration_ms` 等排障信息。
- README 旧示例中的 `[log] file = "..."` 继续可用；新配置推荐使用 `[log.file] path = "..."`。
- HTTP MCP 新增可信反代 Host allowlist，用于后端监听 loopback、反向代理保留公网 Host 的部署方式。
- 默认 Host 保护不变。未配置可信 Host 时，loopback 后端仍会拒绝非 localhost Host。

## 配置示例

```toml
[log]
level = "info"
format = "json"

[log.file]
path = "/var/log/xuanchu/xuanchu.log"
rotate = "daily"

[server.mcp]
trusted_proxy_hosts = ["xuanchu.example.com"]
```

nginx 应保留真实 Host：

```nginx
proxy_set_header Host $host;
```

不要把 Host 改写成 `127.0.0.1:<port>` 作为长期部署方案。显式 allowlist 能同时保留真实入口 Host 和 MCP SDK 的默认安全边界。

## 安全边界

operation log 不记录 Bearer token、admin token、webhook secret、HTTP request/response body、渲染后的 Authorization header 或大段自由文本。权限审计仍以数据库 audit log 为准，operation log 只用于运行时排障。
