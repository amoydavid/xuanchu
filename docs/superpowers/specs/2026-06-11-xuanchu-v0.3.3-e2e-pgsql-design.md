# Xuanchu v0.3.3 E2E 与 PostgreSQL 覆盖补强设计

## 背景

v0.3.2 已修复 server operation log 落盘和 HTTP MCP 反向代理 Host allowlist。当前自动化测试覆盖有三类：

- `tests/integration/cli_test.go` 会构建真实 `xuanchu` 二进制并启动 server，但默认使用 SQLite。
- `internal/storage/postgres_test.go` 可通过 `XUANCHU_TEST_DB_URL` 跑 PostgreSQL storage 层测试，但不覆盖真实 CLI/server/MCP 流程。
- `internal/httpapi` / `internal/mcpserver` 有 in-process 的 HTTP/MCP 测试，但没有覆盖 PostgreSQL 后端上的真实进程 E2E。

2026-06-11 手动 smoke 已验证：本地 PostgreSQL 新数据库上可以完成 storage 测试、真实 server 启动、日志落盘、`/mcp` Host allowlist 的 403/401 行为。但这还不是可重复的自动化测试。

## 目标

v0.3.3 的主要目标是提升发布前验证可信度，不新增用户可见功能。

- 增加 opt-in PostgreSQL E2E 测试，默认没有 PostgreSQL 环境时跳过。
- E2E 使用真实 `xuanchu` 二进制、真实 `xuanchu server` 进程、真实 PostgreSQL 临时数据库。
- 覆盖 PostgreSQL migration/bootstrap、token 创建、HTTP `/healthz`、HTTP `/api/v1/me`、HTTP MCP Host allowlist、operation log 文件落盘。
- 保持 `CGO_ENABLED=0` 测试和构建要求。
- 测试结束必须清理临时数据库和 server 进程。

## 非目标

- 不新增 MCP tool。
- 不实现 `task_search`。
- 不做多端 sync。
- 不要求默认 `go test ./...` 依赖本机 PostgreSQL。
- 不在 release 文档中加入验收清单。

## PostgreSQL E2E 环境契约

新增环境变量：

```bash
XUANCHU_E2E_POSTGRES_ADMIN_URL=postgres://mac@127.0.0.1:5432/postgres?sslmode=disable
```

测试 helper 使用该 admin URL 创建唯一临时数据库，例如 `xuanchu_e2e_<timestamp>_<pid>`，再构造被测 DB URL：

```text
postgres://mac@127.0.0.1:5432/xuanchu_e2e_<suffix>?sslmode=disable
```

如果 `XUANCHU_E2E_POSTGRES_ADMIN_URL` 为空，E2E PostgreSQL 测试跳过。

## 验证边界

E2E 测试应断言：

- `xuanchu --db-url <pg-url> --json token create ...` 可以完成首次 migration/bootstrap 并返回 raw token。
- `xuanchu server --db-url <pg-url> --config <toml> --listen 127.0.0.1:0` 可以启动。
- `/healthz` 返回 200。
- `/api/v1/me` 携带 Bearer token 返回 200，并使用 PostgreSQL 中的 token/user/workspace。
- `/mcp` 在 loopback 后端上收到未信任公网 Host 返回 403。
- 配置 `trusted_proxy_hosts = ["xuanchu.example.com"]` 后，`Host: xuanchu.example.com` 的 `/mcp` 请求能通过 Host guard，缺 token 时返回 401。
- 日志文件包含 `server_listening`、`http_request`、`shutdown_signal`，且 HTTP access log 包含 `workspace_id` / `workspace_ref`。
