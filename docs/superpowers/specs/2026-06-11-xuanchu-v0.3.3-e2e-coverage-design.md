# Xuanchu v0.3.3 E2E 覆盖补强设计

## 背景

v0.3.2 已修复 server operation log 落盘和 HTTP MCP 反向代理 Host allowlist。继续只围绕这两个点补测试是不够的：Xuanchu 已经是单二进制、多入口、多后端的任务运行时，发布前需要有一组稳定的端到端黄金路径，覆盖真实进程、真实存储、真实 HTTP/MCP/Remote 行为，而不是只依赖 in-process 单元测试。

当前自动化测试覆盖大致如下：

- `tests/integration/cli_test.go`：构建真实 `xuanchu` 二进制，覆盖大量本地 CLI、远程 CLI、server、stdio MCP smoke，但主要使用 SQLite。
- `internal/httpapi/*_test.go`：覆盖 HTTP API、权限、impersonation、hook/notification lifecycle，多数是 in-process server。
- `internal/mcpserver/integration_test.go`：覆盖 MCP tool/resource 的绝大多数功能，多数是 in-process MCP server/session。
- `internal/hookruntime` / `internal/notificationruntime` / `internal/app`：覆盖 dispatcher、scheduler、模板和可靠投递关键规则，多数是组件级测试。
- `internal/storage/postgres_test.go`：通过 `XUANCHU_TEST_DB_URL` opt-in 覆盖 PostgreSQL migration/bootstrap 与部分 repo CRUD，但不覆盖真实 CLI/server/MCP 流程。

这说明“测试很多”，但 E2E 覆盖仍有结构性缺口：跨入口一致性、真实进程 server、PostgreSQL 后端、运行时 dispatcher、日志/audit 联动、升级迁移与失败边界没有形成清晰的发布前覆盖矩阵。

## 目标

v0.3.3 的主要目标是提升发布前验证可信度，不新增用户可见功能。

- 定义并实现 E2E 覆盖矩阵，覆盖核心用户旅程和运维旅程。
- 默认 `go test ./...` 继续可在无 PostgreSQL、无外部服务的环境中运行。
- PostgreSQL E2E 通过显式环境变量 opt-in，并自动创建/删除临时数据库。
- E2E 测试尽量使用真实 `xuanchu` 二进制、真实 `xuanchu server` 进程、真实 HTTP 请求、真实 MCP transport。
- 覆盖 SQLite 默认路径和 PostgreSQL opt-in 两类后端。
- 覆盖成功路径和关键失败边界：权限拒绝、workspace/project scope 隔离、MCP Host guard、body limit、secret 不泄露、日志字段落盘。
- 保持 `CGO_ENABLED=0` 测试和构建要求。

## 非目标

- 不新增 MCP tool。
- 不做多端 sync。
- 不要求默认 `go test ./...` 依赖本机 PostgreSQL。
- 不引入 docker/testcontainers 作为默认测试依赖。
- 不在 release 文档中加入验收清单。

## E2E 覆盖矩阵

### A. 本地 CLI 核心任务黄金路径

已有覆盖较强，但需要收敛成一个稳定 smoke：

- local SQLite bootstrap。
- task add/list/info/modify/start/stop/done/delete。
- assignee、project、task_slug、query/report/urgency 的最小组合。
- export/import roundtrip。

v0.3.3 不需要重写全部已有测试，只需要保留并命名一条短平快 smoke，作为发布前快速入口。

### B. 远程 CLI + HTTP API 黄金路径

已有 `TestCLIRemote*` 和 HTTP in-process 测试，但需要一条真实 server 进程覆盖：

- 用本地 CLI 创建 token。
- 启动真实 server。
- 用 remote CLI 连接 server 创建/修改/查询 task/project。
- 验证远程操作不写入 remote client 的本地 DB。
- 验证 HTTP `/api/v1/me`、`/api/v1/tasks`、`/api/v1/projects` 与 remote CLI 结果一致。

### C. HTTP MCP 黄金路径

已有 stdio MCP smoke 和 in-process MCP tool coverage，但真实 HTTP MCP 只覆盖缺 token/body limit 等边界。需要补：

- 真实 server + Bearer token + HTTP MCP initialize/tools/list/call。
- 调用 `task_add` 和 `task_query`，断言 `structuredContent` 可用，不只看 rendered text。
- 验证 workspace-scoped token 可在 workspace 内跨 project 操作。
- 验证 project allowlist token 不能越权。
- 验证反代 Host allowlist：未信任 Host 403，可信 Host 进入 auth middleware。

### D. stdio MCP 黄金路径

已有 `TestMCPStdioListTools` 和 `TestCLIMCPStdioOutputsJSONRPC`，但缺少真实 stdio tool 调用 smoke：

- 通过 `mcp.CommandTransport` 启动真实 `xuanchu mcp stdio`。
- 调用 `task_add` / `task_query`。
- 验证 stdout 只输出 JSON-RPC，不混入日志。
- 验证 operation log 可写入配置文件或 stderr 不污染 protocol。

### E. Hook / Notification / Dispatcher 运行时 E2E

已有 in-process hook e2e 和 dispatcher 单测，但真实 server 运行时链路不足：

- 启动真实 server 后自动运行 hook dispatcher、notification dispatcher、reminder scheduler。
- 配置本地 `httptest.Server` 作为 sink。
- 通过 HTTP API 或 CLI 创建 sink、hook、notification rule、reminder rule。
- 写 task/project 动作，等待 delivery 投递到 sink。
- 验证 delivery 状态、operation log、secret 不出现在 payload/view/log。
- 验证 retry/dead-letter 至少有一个真实进程 smoke。

这部分可以先做一条最小 smoke，不要求覆盖所有事件类型。

### F. PostgreSQL 后端 E2E

PostgreSQL 是 opt-in：

```bash
XUANCHU_E2E_POSTGRES_ADMIN_URL=postgres://mac@127.0.0.1:5432/postgres?sslmode=disable
```

测试 helper 使用该 admin URL 创建唯一临时数据库，例如 `xuanchu_e2e_<timestamp>_<pid>`，再构造被测 DB URL。测试结束必须断开连接并 `DROP DATABASE IF EXISTS`。

PostgreSQL E2E 至少覆盖：

- migration/bootstrap。
- token 创建。
- 真实 server `/healthz`、`/api/v1/me`。
- HTTP MCP Host allowlist。
- operation log 文件落盘，包含 `workspace_id` / `workspace_ref`。
- task/project 基础写入与查询。

### G. 升级 / 迁移 / 数据兼容 E2E

当前已有 migration warning 和 storage migration 单测，但缺少面向发布的升级 smoke：

- 准备一个最小旧 schema/旧数据 fixture。
- 启动当前二进制触发 migration。
- 验证核心数据可读写，migration warning 不污染 stdout JSON。
- SQLite 必做；PostgreSQL 可先在 storage 层保留，后续再扩展真实进程。

## 优先级

v0.3.3 必做：

1. 真实 server + remote CLI/API 黄金路径。
2. 真实 HTTP MCP tool 调用黄金路径。
3. 真实 stdio MCP tool 调用黄金路径。
4. Hook/Notification runtime 最小真实进程 smoke。
5. PostgreSQL opt-in E2E。
6. README 中的 E2E 运行说明。

v0.3.3 可延后：

- 大 workspace 性能 E2E。
- 多实例 dispatcher 竞争 E2E。
- 全量历史版本升级矩阵。
- 外部系统 adapter E2E。
