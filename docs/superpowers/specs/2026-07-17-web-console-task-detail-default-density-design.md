# Web Console 任务详情页低噪声默认态设计

**日期：** 2026-07-17
**状态：** 已实现
**范围：** 仅调整 Workspace Web Console 的任务详情页信息密度与动作层级；不改任务、链接、子任务或审计的服务端契约。

## 1. 问题与目标

当前详情页把链接、子任务、完整注解编辑器和全部计划字段同时铺在首屏。普通任务通常没有链接或子任务，空态因此挤占正文；顶部的开始、完成、更多和返回项目也没有清晰的动作优先级。

本次目标是让默认页首先服务于「理解并推进一条任务」，只有任务实际出现关联资料、子任务或讨论时，页面才展示对应复杂度。

## 2. 设计决策

### 2.1 渐进披露

- 没有关联资料时，不渲染「关联资料 / 暂无链接」区块；没有子任务且未打开 composer 时，不渲染「子任务 / 暂无子任务」区块。
- 顶部更多菜单为可写的普通任务提供「添加关联资料」和「添加子任务」。前者打开既有链接弹窗；后者在正文和活动之间展开既有就地 composer。
- 保存首条关联资料或子任务后，对应区块出现并持续显示。删除最后一条关联资料后，区块重新隐藏。
- 移动端子任务 tab 只在已有子任务或 composer 已打开时出现；从更多菜单触发创建时切换至该 tab。

### 2.2 动作层级

| 层级 | 动作 | 组件样式 |
|---|---|---|
| 主动作 | 完成任务；已展开编辑器内的提交 | `default` |
| 次动作 | 开始、暂停、重新打开 | `outline` |
| 局部/低频动作 | 编辑/添加描述、写更新、更多、编辑删除行项目 | `ghost` |

项目路径已在面包屑可点击，因此详情页标题区不再重复渲染「返回项目」按钮。删除仍只位于更多菜单的危险区。

### 2.3 右栏与活动

- 可写任务的计划字段全空时，计划分组保持折叠；任一计划字段存在时默认展开。
- 外部链接不是任务依赖关系；它不能触发右栏「关系」分组。
- 活动区默认只显示轻量「写更新」入口和已有时间线。点击入口后才展开 Markdown 编辑器；提交成功后收起。注解与变更历史都去除独立卡片边框，以同一时间线密度呈现。

## 3. 约束与验收

- 保持现有权限：completed/deleted、关闭项目或无 task:write 时不得出现创建入口。
- 保持子任务创建的 `parent`、项目继承、Enter 连续创建和链接 CRUD 契约。
- 保持循环实例动作与系列入口；循环任务不显示手动子任务创建入口。
- 中文与英文 locale 同步。
- 定向 Vitest 覆盖空态隐藏、更多菜单打开两类创建入口、完成动作主按钮、空计划折叠、活动编辑器按需展开。
- 运行 `pnpm --dir web typecheck`、`test`、`lint`、`build`、`smoke:editing` 与 `git diff --check`。

## 4. 非目标

- 不新增附件数据模型、不新增链接类型字典、不改变依赖编辑能力。
- 不合并注解与审计 API，也不改变其排序契约。
- 不改变桌面两栏布局、任务字段或后端接口。
