# v0.4.2 Project Readonly View 与 SSO 入口预留

**日期：** 2026-06-12
**状态：** 草案
**版本：** v0.4.2
**对应 ROADMAP：** v0.4.0 Web Admin Console 后续增强

## 1. 背景

v0.4.0 已经把 Web Console 放到单一 `xuanchu` 二进制内，普通用户通过 `/` 输入 PAT / Agent token 登录。v0.4.1 继续补齐了 server admin bootstrap 入口，但普通 workspace 用户的浏览器体验仍然偏运维资源表格，不适合作为“从企业协作工具点开后查看某个项目任务情况”的目标页。

新的需求是：企业内部系统或飞书消息中可以发送一个项目链接，用户点击后进入 Xuanchu，看到某个 workspace 下某个 project 的任务情况。链接形态应表达 Xuanchu 的真实隔离层级：

```text
https://xuanchu.example.com/workspaces/{workspaceSlug}/projects/{projectSlug}
```

这个版本暂不接入飞书授权，也不实现企业授权中心。v0.4.2 只把页面、路由、数据读取和登录后回跳做好，为下一步企业 SSO / 飞书授权中心接入预留清晰边界。

## 2. 核心判断

### 2.1 URL 必须携带 workspace 层级

`project.slug` 只在同一 workspace 内唯一，不是全局唯一标识。因此项目页不能设计成：

```text
/projects/{projectSlug}
```

必须使用：

```text
/workspaces/{workspaceSlug}/projects/{projectSlug}
```

服务端和前端都不能把 project slug 当作全局身份。所有数据请求必须带上 workspace ref，并在后端解析 project 时校验该 project 属于这个 workspace。

### 2.2 v0.4.2 只做只读项目页

这个页面面向从企业协作工具点进来的普通成员，首要目标是“快速判断项目任务情况”。它不是完整项目管理系统，也不是拖拽看板。

首版只读，不提供任务编辑、完成、删除、改负责人、改优先级等操作。只读不是权限绕过；页面仍然使用当前登录用户身份访问 `/api/v1/*`，后端继续检查 membership、token scope、workspace allowlist、project allowlist 和 role permission。

### 2.3 不实现 SSO，但路由要为 SSO 预留

v0.4.2 不实现：

- `/sso/{provider}`
- `/sso/{provider}/callback`
- 企业授权中心协议
- 飞书 OAuth
- cookie web session
- 外部身份自动绑定

但页面和登录流程要为后续 SSO 做好两个预留：

1. 任何受保护页面未登录时，必须能把原始目标路径作为 `redirect` / `next` 保存下来。
2. 登录成功后必须回到原始项目页，而不是固定进入概览页。

后续 v0.4.3 或更高版本可以把：

```text
/sso/company?redirect=/workspaces/acme/projects/agentapi
```

接到企业授权中心。v0.4.2 只保证目标页面和回跳语义存在。

### 2.4 飞书链接不携带 Xuanchu token

飞书卡片或企业内部消息中的按钮只能携带普通 URL：

```text
https://xuanchu.example.com/workspaces/acme/projects/agentapi
```

不得携带：

```text
?token=...
?agent_token=...
?admin_token=...
```

原因：

- URL 会进入浏览器历史、代理日志和飞书链接预览。
- token 泄露后难以追踪。
- 使用 URL token 会绕开当前会话边界，后续接入 SSO 时也会形成兼容包袱。

## 3. 目标

v0.4.2 完成后应支持以下流程：

1. 用户点击企业消息中的项目链接：

   ```text
   /workspaces/acme/projects/agentapi
   ```

2. 如果当前 tab 已有有效 Xuanchu token，页面直接展示项目任务情况。
3. 如果当前 tab 未登录，前端展示普通登录页，并保留目标路径。
4. 用户输入 PAT / Agent token 登录成功后，自动回到原始项目页。
5. 页面读取项目元数据和项目内任务列表。
6. 页面展示项目概览、任务状态分布、逾期/高优先级/负责人摘要和任务列表。
7. 用户点击任务标识或任务描述后，进入同一项目上下文下的任务只读详情页。
8. 任务详情页提供明确的“返回项目”入口。
9. 如果用户没有 workspace、project 或 task 读取权限，展示明确的无权限或不存在状态。

## 4. 非目标

v0.4.2 不做以下内容：

- 不接入飞书 OAuth。
- 不接入企业授权中心。
- 不实现 OIDC / OAuth2 provider 配置。
- 不新增 web session cookie。
- 不新增自动开户或自动加入 workspace。
- 不新增项目写操作。
- 不做拖拽看板。
- 不做任务详情编辑抽屉或任何任务写操作；只读任务详情页允许进入和返回。
- 不做评论流、富文本活动流或实时协同。
- 不做项目 dashboard BI。
- 不做公网匿名分享链接。
- 不做一次性外链 token。
- 不做飞书卡片发送能力。
- 不修改 server admin 控制面。

## 5. 信息架构

### 5.1 新增页面

```text
/workspaces/:workspaceSlug/projects/:projectSlug
/workspaces/:workspaceSlug/projects/:projectSlug/tasks/:taskRef
```

页面名称：

```text
Project Readonly View
项目只读视图
```

该页面属于普通 workspace Console，不属于 `/admin/*` server admin 控制面。

### 5.2 页面数据

页面至少需要以下数据：

```text
GET /api/v1/projects/{projectSlug}?workspace={workspaceSlug}
GET /api/v1/tasks?workspace={workspaceSlug}&project={projectSlug}&limit=200
GET /api/v1/tasks/{taskRef}?workspace={workspaceSlug}
GET /api/v1/projects/{projectSlug}/timeline?workspace={workspaceSlug}&limit=20
```

其中 timeline 可以在首版降级为可选。如果当前 HTTP API 没有 `limit` 参数或 timeline 参数不完整，v0.4.2 不强行扩展复杂查询，页面可以先展示项目元数据和任务列表。

任务列表读取应尽量使用已有 `GET /api/v1/tasks` 的 `workspace`、`project`、`limit`、`sort`、`query/filter` 参数。缺失的统计指标可以在前端基于返回任务列表计算，但页面必须标注这些统计来自当前加载范围，避免把 `limit=200` 当作全量事实。

### 5.3 权限要求

页面所需最低权限：

```text
project:read
task:read
```

有效权限仍然是：

```text
membership role 权限
∩ token capability scope
∩ token workspace scope
∩ token project scope
```

如果 token 缺少 `project:read`，项目元数据读取失败。如果 token 缺少 `task:read`，任务列表读取失败。页面应分别处理这两类失败，不要把所有错误都显示为“项目不存在”。

## 8. API 复用与缺口

### 8.1 可复用现有 API

v0.4.2 优先复用：

```text
GET /api/v1/projects/{projectRef}?workspace={workspaceSlug}
GET /api/v1/tasks?workspace={workspaceSlug}&project={projectSlug}&limit=200
GET /api/v1/tasks/{taskRef}?workspace={workspaceSlug}
GET /api/v1/projects/{projectRef}/timeline?workspace={workspaceSlug}
```

这些接口已经在普通 API 权限链路下工作，页面不需要 console-only API。

### 8.2 可选新增轻量查询参数

如果现有 timeline 不支持 `limit`，可以不改。如果任务页需要更稳定排序，可以使用已有 `sort` 参数。v0.4.2 不新增聚合统计 API；统计先在前端基于当前加载结果计算。

如果后续大 workspace 需要准确全量统计，再设计：

```text
GET /api/v1/projects/{projectRef}/summary?workspace={workspaceSlug}
```

该 endpoint 不进入 v0.4.2。

## 9. 登录回跳

当前普通登录页应支持来源路径：

```text
/login?redirect=/workspaces/acme/projects/agentapi
```

或在 SPA 内部 state 保存同等语义。考虑到当前 `/` 就是登录入口，v0.4.2 可以采用：

```text
/?redirect=/workspaces/acme/projects/agentapi
```

规则：

- 只接受以 `/` 开头的站内相对路径。
- 拒绝 `//evil.example.com`。
- 拒绝 `https://evil.example.com`。
- 拒绝包含控制字符的路径。
- 登录成功后 `router.navigate({ to: redirect })`。
- 登录失败不丢失 redirect。
- 用户点击退出后，如果当前页是项目页，可以回到登录页并继续保留 redirect。

这部分不是 SSO，但它是后续 SSO 的前置能力。

## 10. 后续 SSO 预留

后续企业授权中心接入建议使用：

```text
GET /sso/{provider}?redirect=/workspaces/acme/projects/agentapi
GET /sso/{provider}/callback?code=...&state=...
```

v0.4.2 不实现上述 endpoint，只在 spec 中冻结未来方向：

- `provider` 是 Xuanchu 配置中的 SSO provider id，不是写死的飞书实现。
- `redirect` 仍然只允许站内相对路径。
- 企业授权中心与 Xuanchu 之间必须使用可验证的 code exchange 或 signed id token。
- 企业授权中心可以在内部完成飞书 OAuth，但 Xuanchu 不直接保存飞书 app secret。
- Xuanchu 最终只接收稳定 subject，例如：

  ```text
  provider = "company_sso"
  external_id = "feishu:user_id:ou_xxx"
  ```

- `name` 只用于展示或同步，不作为身份主键。
- SSO 登录成功后仍然必须检查 Xuanchu workspace membership 和 project 权限。

## 12. 测试与验收

### 12.1 前端测试

至少覆盖：

- 未登录访问 `/workspaces/acme/projects/agentapi` 时显示登录页并保留 redirect。
- 登录成功后跳回项目页。
- 项目页调用带 workspace/project 的 API。
- 项目页展示项目标题、统计卡片和任务列表。
- 任务列表中的任务标识或描述可以跳转到任务详情页。
- 任务详情页调用带 workspace 的 task detail API，展示任务字段和注记。
- 任务详情页提供稳定返回项目页的链接。
- 403 显示无权限状态。
- 404 显示项目不存在或不可见。
- 空任务列表显示空项目状态。
- 中文/英文切换后核心文案正确。
- 移动端任务列表不会依赖宽表格。

场景：

- 桌面宽度。
- 移动宽度。
- light mode。
- dark mode。
- 未登录回跳。
- 已登录展示真实 API 数据。

不得用假数据作为验收结果。

## 13. 验收标准

v0.4.2 完成后：

- 企业协作工具可以安全地发送 `/workspaces/{workspaceSlug}/projects/{projectSlug}` 链接。
- 用户未登录时可以登录后回到原项目页。
- 用户已登录时可以直接看到项目只读任务情况。
- 用户可以从项目任务列表进入任务只读详情页，并从详情页返回项目页。
- 页面数据全部来自现有 HTTP API，不使用 mock 数据作为结果。
- 页面不暴露任何写操作。
- 页面不在 URL、localStorage 或日志中泄露 PAT / Agent token。
- workspace/project 权限继续由后端强制校验。
- URL、路由和登录回跳可以自然接入后续企业 SSO。
