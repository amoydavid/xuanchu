# v0.1.1 Task Slug Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Xuanchu 增加稳定短任务标识 `task_slug`，格式为 `<projectSlug>-<seq>`，并在 CLI、HTTP、Remote CLI、MCP、Hook 中统一可读可解析。

**Architecture:** `project.slug` 收紧为 3-10 位英文数字并统一小写；`projects.next_task_seq` 管理 project 内递增序号；`tasks.project_seq` 保存任务在当前 project 下的序号；`task_slug` 由 `project + project_seq` 派生，不单独持久化。App 层新增 resolver mode，交互入口允许数字 working-set ID，协议入口只允许 UUID / `task_slug`。

**Tech Stack:** Go 1.25, Cobra, GORM, `github.com/glebarez/sqlite`, `gorm.io/driver/postgres`, `github.com/google/uuid`, `github.com/modelcontextprotocol/go-sdk/mcp`

**Spec:** `docs/superpowers/specs/2026-06-07-v0.1.1-task-slug-design.md`

```go
func normalizeProjectSlug(slug string) (string, error) {
    slug = strings.TrimSpace(strings.ToLower(slug))
    if len(slug) < 3 || len(slug) > 10 {
        return "", RuntimeError{Code: "project_invalid_slug", Message: fmt.Sprintf("project slug %q must be 3-10 lowercase letters or digits", slug)}
    }
    if slug[0] < 'a' || slug[0] > 'z' {
        return "", RuntimeError{Code: "project_invalid_slug", Message: fmt.Sprintf("project slug %q must start with a letter", slug)}
    }
    for _, ch := range slug {
        if (ch >= 'a' && ch <= 'z') || (ch >= '0' && ch <= '9') {
            continue
        }
        return "", RuntimeError{Code: "project_invalid_slug", Message: fmt.Sprintf("project slug %q is invalid", slug)}
    }
    return slug, nil
}
```

保留现有 `project_slug_immutable` 行为，不引入 slug rename。

  - 新增仅在 tx-bound repository 上调用的低层方法，例如：

```go
func (r *ProjectRepository) AllocateProjectTaskSeqLocked(workspaceID, projectID string) (int64, error) {
    var project Project
    q := r.db.Where("workspace_id = ? AND id = ?", workspaceID, projectID)
    if r.db.Dialector.Name() == "postgres" {
        q = q.Clauses(clause.Locking{Strength: "UPDATE"})
    }
    if err := q.First(&project).Error; err != nil { ... }
    seq := project.NextTaskSeq
    if err := r.db.Model(&Project{}).
        Where("workspace_id = ? AND id = ?", workspaceID, projectID).
        Update("next_task_seq", seq+1).Error; err != nil { ... }
    return seq, nil
}
```

事务边界由 app 层掌控：现有 `withAuditAndEvents` / `Store.Transaction` 会创建 tx-bound `Service`，该 tx service 的 `projectRepo` 和 `repo` 都绑定同一个 `txStore.DB()`。在 `tx.addLocked` / `tx.modifyLocked` / `tx.createNextRecurringChild` 内先调用 `tx.projectRepo.AllocateProjectTaskSeqLocked(...)`，再用同一个 `tx.repo.Create/Update(...)` 写任务。不要在 storage 方法内部开启一个与 app 写任务分离的事务。

新增测试必须覆盖：

- `Add` 写任务失败时 `next_task_seq` 不递增。
- `Modify` 移动 project 写失败时 `next_task_seq` 不递增。
- recurring child 写失败时 `next_task_seq` 不递增。
