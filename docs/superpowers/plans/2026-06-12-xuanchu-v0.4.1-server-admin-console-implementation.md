# Xuanchu v0.4.1 Server Admin Console Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:subagent-driven-development` (if subagents available) or `superpowers:executing-plans` to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v0.4.0 Web Console 基础上补齐 server admin bootstrap 闭环，让浏览器可以用 `xuanchu_admin_...` 创建 workspace、创建或提升 workspace 管理员，并为该管理员签发 workspace-scoped Agent token。

**Architecture:** 后端继续保持 server admin 与普通 workspace API 隔离：`/api/v1/admin/*` 只接受 admin token，普通 `/api/v1/*` 只接受 PAT / Agent token。前端使用 TanStack Router 分出 workspace console 与 admin control-plane 两棵路由树，两个 session 使用不同 storage key、不同 API client、不同 guard。`App.tsx` 只挂 `RouterProvider`，业务能力按 `features/<domain>/<capability>` 放置。

**Tech Stack:** Go 1.25、GORM、SQLite/PostgreSQL 双后端、React、Vite 8.x、TypeScript、pnpm、shadcn/ui、Tailwind、TanStack Router、TanStack Query、i18next、lucide-react、Vitest、Testing Library、`go:embed`、`CGO_ENABLED=0`。

---

## v0.4.1 修订：DB Admin Token 与 setup-code

2026-06-12 修订后，v0.4.1 不再把配置文件 admin token verifier 作为主路径。`[server.admin].enabled` 只作为控制面总开关；长期 admin token verifier 存入数据库 `server_admin_tokens`。当服务启用 admin 控制面但数据库中没有有效 admin token 时，server 启动时生成一次性 setup-code 并输出到控制台，浏览器通过 `/admin/setup` 输入 setup-code 生成第一个 `xuanchu_admin_...` token。

### 关键验收

- 配置文件不需要写长期 admin token hash，也不需要重启即可使用新 admin token。
- `GET /api/v1/admin/status` 匿名返回 `disabled` / `setup_required` / `login_required`。
- 无有效 admin token 时，`GET /api/v1/admin/session` 返回 `401 admin_setup_required`。
- `POST /api/v1/admin/setup` 用正确 setup-code 生成 raw admin token，一次性返回，并写入 `server_admin_tokens`。
- setup 成功后同一进程内立刻可以用新 token 调用 `/api/v1/admin/session`。
- setup-code 不落库、不通过 API 返回、不进入日志。
- 旧 `[[server.admin.tokens]]` 仍可作为兼容 verifier 使用，但文档标记 deprecated。
